References

Running registry of papers, repos, announcements, and open questions.

Running registry for the personal research lab. Append-only in spirit; prune quarterly.

Conventions

  • Every entry gets a pillar tag: [R] runtime/harness, [E] environments/verification, [T] training/optimization, [M] meta/RSI.
  • Every entry gets a status: queued / read / used / contributed.
  • If an entry drives a notebook post, link the post slug next to it. An entry that never earns a link after two quarters gets pruned.
  • Dates are the date I added it, not the publication date.

2. Repos & tools

Runtime / harness [R]

  • Annulus (own) — local-first agentic platform; MVP is SWE, roadmap is MCP + GraphRAG + science/engineering platform.
  • karpathy/autoresearch — minimal autonomous research loop. Study-and-fork target; closest public analogue to Annulus’s second act.
  • NousResearch/hermes-agent — reference architecture: skills-as-procedural-memory, MCP, subagent delegation, programmatic tool calling, trajectory export.
  • NousResearch/hermes-agent-self-evolution — DSPy + GEPA evolutionary optimization of skills/prompts/code. Directly relevant to [M].
  • 0xNyk/awesome-hermes-agent — community directory; useful map of the plugin/skill ecosystem.
  • Claude Code — terminal, repo-scale analysis and architecture. Skills are cross-agent portable (agentskills.io standard).
  • Cursor (Composer 2.5) — inline diffs + ADR review. Current daily driver.

Environments / verification [E]

  • PrimeIntellect-ai/verifiers — v1 (July 10, 2026) decomposes into tasksets / harnesses / runtimes. Dialect adapters for OpenAI Chat Completions, OpenAI Responses, Anthropic Messages.
  • Environments Hub — 2,500+ environments, doubles as a Python package registry (wheels + pyproject.toml).
  • PrimeIntellect-ai/prime-cli — install/upload/manage environments.
  • PrimeIntellect-ai/prime-environments — where RFCs and bounties land.
  • Harbor (fully supported third-party format in verifiers v1); NeMo Gym and OpenEnv in alpha.

Training / optimization [T]

  • PrimeIntellect-ai/prime-rl — FSDP, SFT + RL + evals, Slurm/K8s multi-node, VLM support.
  • Hugging Face TRL — local GRPO baseline; the “no managed infra” leg of the three-stack comparison.
  • Tinker + tinker-cookbook — GA since Dec 12, 2025. Primitives: forward_backward, optim_step, save_state, sample. LoRA-based. Checkpoint download supported.
  • NousResearch/atropos — RL environments framework for LLM trajectories.
  • tinker-atropos (Nous) — standalone Atropos ↔︎ Tinker integration; RL on real agent trajectories. The literal seam between the runtime and training pillars.

Meta / RSI [M]

  • OpenEvolve and similar open AlphaEvolve reproductions — evolutionary program search over a verifier.
  • DSPy / GEPA — prompt and program optimization.

6. Open questions

Living list. Each one is a candidate notebook post or thesis discussion section.

  1. Does an LLM fine-tuned with RLVR on Tesseract approach the self-play agent’s play strength, or plateau? Where exactly?
  2. Can the AlphaZero-lineage agent serve as opponent and evaluator in an LLM RL loop for the same game?
  3. What does the forgetting literature say about weight-updating self-improvement loops? Is forgetting the actual binding constraint on RSI, and does that argue for skills/memory-based improvement over weight updates?
  4. What do Tinker’s primitives buy over TRL’s trainers that is not just convenience — and where does the abstraction leak?
  5. Which of Hermes’s architectural choices (memory model, skills spec, security boundary) should Annulus adopt, and which are wrong for a local-first NASA context?
  6. Where does evolutionary program search stop working — what problem structure does AlphaEvolve-style search require?
